# SurakshaNet architecture

The Compose app signs in with Firebase Email/Password. After email verification the configured client retrieves its profile from FastAPI. The API verifies the ID token and revocation, checks the verified email and UID allowlist, and upserts the PostgreSQL user by Firebase UID. A failed sync can be retried with the existing Firebase session.

PostGIS searches within 1,000 metres of the victim's latest eligible fix. Movement can recruit a new responder. An accepted incident-specific grant lets an earlier responder continue tracking after the radius moves. PostgreSQL records grants and closure. WebSocket clients exchange short-lived tickets for a connection. Redis distributes changes between workers.

The Android installation submits its Firebase Messaging token under the signed-in identity. Invitations use the notification outbox. The self-test endpoint currently sends directly through FCM to the authenticated user's registered installation. A successful Firebase send establishes acceptance only. Receipt, display and opening require separate device observations.

Render terminates HTTPS for the API. The Blueprint connects the owner's existing Render Postgres instance using its internal URL and Key Value service in the same region. Android receives only the HTTPS origin and Firebase client configuration. Public emergency dispatch is outside the demo.
