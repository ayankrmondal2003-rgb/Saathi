# Render deployment for the controlled demo

## Owner setup

1. Supply a private Git repository containing this reviewed project. This Windows workspace had no Git metadata during the review. Before authorizing publication, inspect the staged filenames and run a secret scan including Git history in the actual repository.
2. Before applying, review migrations 0001–0007 against the intended demo database and confirm a recoverable backup. For an existing schema, check its alembic_version and ownership. If application tables already exist without a matching revision, stop and reconcile the schema before deploying. The pre-deploy hook runs during the initial deployment.

   Open the existing **surakshanet_db** in Render. Confirm the workspace, region, PostgreSQL version and recovery window. Copy its **Internal Database URL** privately from Connect. The Blueprint currently selects Singapore for web and Key Value. If the database is elsewhere, change both region entries before applying. The Blueprint leaves the existing database under its current management.
3. In Render Dashboard choose **New → Blueprint**, connect the authorized repository, select the deployment branch, and use the root `render.yaml`. Review the resources, region and charges. An owner must apply the Blueprint.
4. Enter the existing Internal Database URL at the DATABASE_URL prompt. Enter `[]` for TEST_ACCOUNT_UIDS during provisioning. Use the three verified UIDs from [Firebase Admin setup](FIREBASE_ADMIN_SETUP.md) before rehearsal. Place all three resources in the database region. The web service uses the backend directory as its Docker build context. The new Key Value external IP allowlist is empty. Inspect the existing database's external access rules and coordinate any changes with its owner.
5. In the web service open **Environment → Secret Files → Add Secret File**, name it `firebase-admin.json`, paste the dedicated service account JSON there, save, and deploy. The initial deployment can fail before the secret file exists. Keep the real file outside Git and Android.
6. On the Postgres instance check **Recovery** for the available restore window and backups. Before applying to an existing database, confirm the target and take a restorable backup. The pre-deploy command runs `sh render-migrate.sh`, enables PostGIS, and executes `alembic upgrade head` once per deployment. The current migration head is 0007. Do not run downgrade to recover a web deployment.
7. On Key Value review **Connections**. Internal access defaults to network-based trust. During initial provisioning, before admitting phones, select **Enable Internal Authentication** and confirm the restart. Sync the Blueprint and redeploy the web service to refresh its REDIS_URL reference. Render's Key Value connectionString includes credentials when internal authentication is enabled. Confirm readiness and repeat the cross-worker checks. If a deployed client still uses the old URL, keep the exercise paused while refreshing the binding. Keep external access disabled. [Render Key Value](https://render.com/docs/key-value)
8. In **Events** confirm pre-deploy success and healthy web service startup. Copy the actual HTTPS origin shown by Render and run [cloud acceptance](CLOUD_TEST_GUIDE.md).

## Service behavior

Render terminates TLS for Android HTTPS and WSS. Uvicorn listens on the assigned PORT and starts the existing FastAPI factory in two worker processes. Each process starts geofence and notification polling through the application lifespan. PostgreSQL locks and outbox claim leases coordinate those pollers. No separate worker service is needed. Allowlist checks apply to authenticated users, discovery and notification dispatch. A compromised debug client cannot expand the server allowlist.

## Budget

The selected web compute is approximately US$7/month, Postgres US$6/month and Key Value US$10/month, so adding the web and Key Value services costs approximately **US$17/month**. Total cost depends on the existing database plan; a US$6 database gives a US$23 compute baseline. Additional database storage, bandwidth, workspace charges and taxes can increase the bill. The 512 MB web plan shares memory between two Python processes; check peak memory during rehearsal. Free web services can idle and free Key Value has no disk persistence. The Blueprint uses a paid web plan for the pre-deploy migration hook. Review the dashboard estimate before creating resources.
