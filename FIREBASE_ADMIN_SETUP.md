# Firebase identities and server credential

1. Select **surakshanet-c4ec1** in Firebase Console. Under **Project settings → General → Your apps**, verify com.example.surakshanet. Under **Authentication → Sign-in method**, enable Email/Password. Under **Project settings → Cloud Messaging** verify Firebase Cloud Messaging API (V1) is enabled.
2. In Google Cloud IAM for that project, create a dedicated demo service account. Grant **Firebase Authentication Viewer** for the revocation/user lookup and **Firebase Cloud Messaging API Admin** for sending. In **Service Accounts → the demo account → Keys → Add key → Create new key → JSON**, download to a private location outside the workspace.
3. Configure the secret file through Render as described in [deployment](RENDER_DEPLOYMENT.md). The backend checks the certificate project against FIREBASE_PROJECT_ID on startup. Android uses only its Firebase client configuration.
4. Assign three inboxes you control to victim A, initial responder B and newly nearby responder C. Use **Create Account** on each installation; set a distinct password privately. Open each verification email and refresh verification. If an account exists, sign in or reset the password. Email verification precedes backend access.
5. Find each account in **Authentication → Users**. Copy the exact User UIDs into a JSON array of three strings in the Render web service's TEST_ACCOUNT_UIDS environment value. Save and redeploy. A verified Firebase ID token and membership are both required. Device registration does not grant tracking access.
6. Verify a signed-in profile and a self-test on a single phone before starting an incident. Rotate the key after the exercise. [Firebase Admin setup](https://firebase.google.com/docs/admin/setup) · [Android email/password authentication](https://firebase.google.com/docs/auth/android/password-auth)
